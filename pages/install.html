Install

From download to your first client.

Atlas runs as one Node.js service in front of PostgreSQL 16, behind HTTPS. There is no default administrator: you create the owner account with a one-time setup code.

Docker (Linux)

Point a DNS name at the server and open ports 80 and 443; Caddy gets and renews the certificate automatically. Copy .env.example to .env and set PUBLIC_URL, ATLAS_DOMAIN, POSTGRES_PASSWORD, and ATLAS_MASTER_KEY. Generate the key with:

node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"

Then start Atlas and read the setup code from the log:

docker compose -f deploy/docker-compose.yml --env-file .env up -d
docker compose -f deploy/docker-compose.yml logs app | grep "setup code"

Open your PUBLIC_URL, enter the setup code, and create the owner account. The code works only until the first account exists.

A ready-built image is also published for each release: ghcr.io/ithealthtech/nexus-atlas:1.0.1.

Windows Server

Install Node.js 22 LTS and PostgreSQL 16, and create an empty database and user. Download msp-atlas-1.0.1-windows.zip from the latest release, check it against the .sha256 file beside it, and extract it to a folder such as C:\Program Files\MSP Atlas. From an elevated PowerShell prompt:

.\deploy\windows\Install-Atlas.ps1 -PublicUrl https://atlas.example.com -DatabaseUrl "postgres://atlas:<password>@localhost:5432/atlas"

The script creates C:\ProgramData\MSP Atlas (readable only by Administrators and SYSTEM), creates the master key file on first install, and registers the MSPAtlas service to start automatically. The setup code is in C:\ProgramData\MSP Atlas\logs\MSPAtlas.out.log.

i

Atlas listens on 127.0.0.1:4318. Publish it over HTTPS with IIS (URL Rewrite and Application Request Routing) or Caddy for Windows. Add -BackupDir \\nas\atlas-backups to keep backups on another machine.

The master key

The master key protects every encrypted value: vault passwords, one-time code keys, MFA secrets, and the email and Hudu credentials. It also encrypts backups.

!

If you lose the key, encrypted data and backups can't be recovered. Keep a copy in your existing password manager and a sealed printout — never next to database backups.

To rotate it, list the new key first and the old one after it, restart, run npm run rewrap-keys -w @atlas/server, then remove the old key. Keep the old key for as long as you keep backups made with it.

First day

  1. Turn on two-step sign-in for the owner account, and save the recovery codes.
  2. Set up email under Settings → Email (there's a Microsoft 365 preset) so password resets and expiry alerts work.
  3. Add your clients, or import them from Hudu or CSV under Import & export.
  4. Invite technicians and set their client access under People & access.
  5. Open System status and make sure every check is green.

Backups and restore

Atlas backs itself up every night into one encrypted .atlasbak file holding the database and every attachment, and keeps the newest 14. System status → Back up now makes one on demand. Point ATLAS_BACKUP_DIR at a network share or copy the folder off the server.

npm run backup -w @atlas/server -- verify <file.atlasbak>
npm run restore -w @atlas/server -- <file.atlasbak>

A restore reads and checks the whole file before it changes anything, and needs the master key the backup was made with. Stop Atlas first; add --replace to overwrite the current database.

Upgrading

Back up first. With Docker, pull the new image and run docker compose ... up -d. On Windows, extract the new package over the old folder and run the install script again with no arguments; it keeps your settings and key. Database updates run automatically on start.

Full detail, including every setting, is in the deployment guide and the administrator guide.
