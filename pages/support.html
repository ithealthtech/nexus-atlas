Troubleshooting

Most problems show up on System status first. Start there, then search below.

Symptom finder

Search troubleshooting

Type a symptom, a setting, or a screen name.

I lost the setup code

With Docker, read it from the log: docker compose -f deploy/docker-compose.yml logs app | grep "setup code". On Windows it is in C:\ProgramData\MSP Atlas\logs\MSPAtlas.out.log. It works only until the first account exists. To choose your own, set ATLAS_SETUP_CODE before first start.

Atlas refuses to start in production

Production needs an https:// PUBLIC_URL and a master key (ATLAS_MASTER_KEY or ATLAS_MASTER_KEY_FILE). The log names the missing setting.

Someone is locked out after too many attempts

Wait 15 minutes, or an administrator can use Reset sign-in on their account.

The owner lost their phone and recovery codes

Another owner or administrator can reset their sign-in. If there is none, contact whoever runs the server.

A technician can't see a client

By design, a client someone can't access looks exactly like a missing one. Check their access level for that client, their groups, and their role under People & access.

A password shows but can't be revealed

Revealing needs edit-and-passwords access for the client, a place on the entry's restriction list if it has one, and a reason if the client requires reasons.

Email isn't sending

Use Settings → Email → Send test; it shows the mail server's error. For Microsoft 365, turn on Authenticated SMTP for the mailbox, and use an app password if it has MFA.

Backups are failing or on the same disk

Read the error on System status. Check that the backup folder exists, Atlas can write to it, and the disk isn't full. Point ATLAS_BACKUP_DIR at a network share to clear the same-disk warning.

Restoring a backup fails with a key error

A backup can only be read with the master key it was made with. After a rotation, list the old key after the new one and try again.

Verify now reports a break in the security log

Someone changed the database directly. Keep the server as it is, export the security log, and investigate. Restore from a backup if needed.

A Hudu import stopped partway

Run it again. The importer updates what it already brought in rather than duplicating it, and a stuck run is picked up again automatically.

Still stuck?

Open an issue.

Use GitHub Issues for verified defects. Never include passwords, master keys, API keys, client data, or screenshots containing secrets. Report suspected vulnerabilities privately through the security policy.
